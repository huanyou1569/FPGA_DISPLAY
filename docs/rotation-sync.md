# 灰度测速与显示同步修复日志 · 2026-11-03

工程根目录：`C:/Users/1569/Desktop/test`，PYNQ-Z2 / XC7Z020，PL 时钟 125 MHz。目标仍为 **15 转/秒、120 面/转**。本次不改画笔、贪吃蛇、俄罗斯方块的游戏逻辑和按键协议。

## 原因与边界

用户确认灰度调零面的功能正常，说明有灰度信号进入角度对齐链路。检查旧代码发现：

1. `index_sync.v` 接受脉冲用于对齐后，仍只将 **600～1200 RPM** 的周期判为有效。PS 的 RPM 计算同时要求锁定和周期有效，因此 540 RPM 等实际转速会被回传为 0，扫描间隔也不会随它更新。
2. 第一条脉冲被当成自上电以来的完整一圈，包含电机启动前的等待时间。
3. 500 ms 无脉冲后虽已退出锁定，旧有效标志和扫描时序仍保留；自由显示的参考转速与扫描时序可能不一致。
4. 原先每行单独锁存新的扫描时间，同一面中可能混入两种行周期。旧 `DLY` 只计算理论周期/120，无法证明扫描器实际采用了它。

以上为代码中确认的问题。尚未读取本次实机转速值，不能断言实机当时一定是 540 RPM。当前系统只枚举到 COM3、COM4，没有发现板卡 USB 调试串口 COM16，因此未进行实机串口捕获。

## 修改

- 保留 256 时钟高/低电平滤波，以及 36 ms 的脉冲拒绝窗口。取消 600～1200 RPM 的软件目标带限制，完整有效测量范围约 **120～1667 RPM**。500 ms 无有效脉冲即失锁；手动极慢转动仍可能超时。
- 首个脉冲仅记录起点，第二个脉冲才产生完整周期；修正计数差一个时钟的问题。失锁清除测量有效标志，重新捕获时也从首圈开始。
- `rev_timing` 按实测周期计算扫描行保持时间；失锁恢复默认保持时间 1330。新的保持时间在整面边界锁存，32 行使用同一设置。
- 实际每面间隔由顶层统计相邻 `frame_done` 的时钟差，再由 PS 回传；不再用理想值代替实际扫描值。`DLY` 单位为 μs，整数向下取整；包括无传感器时的实际自由扫描间隔。
- 新增独立 `vx_sync.c/.h`，RPM 使用 64 位整数及四舍五入；周期与诊断寄存器采用同一 AXI 快照。保留旧 `STATUS` 命令格式和游戏响应，增加每秒一行 `SYNC` 状态；USB 调试串口也输出该行。
- CH9141 上位机增加中文同步反馈，无需改蓝牙接线或重配 CH9141。

电机速度由外部驱动器决定。这些代码测量速度并调整显示扫描，不会控制电机自动达到 15 转/秒。

## 实际扫描时序

固定 HUB75 移位/锁存部分不变，仍采用 `col_ofs=3`、129 个移位脉冲、32 行地址：

```text
line_clocks = floor(revolution_clocks / (120 × 32))
hold_max = clamp(line_clocks - 840, 80, 6000)
actual_slice_clocks = 32 × (840 + hold_max)
RPM = round(60 × 125000000 / revolution_clocks)
```

稳定跟随时，120 面的累计整数取整误差小于 3840 个时钟，即 30.72 μs/转；零面仍按灰度脉冲在显示面边界对齐。转速发生变化时，先测完一圈，再完成除法并在后续面边界生效。

| 输入转速 | 实测一转时钟 | 行保持值 | 实际每面时钟 | 实际每面间隔 |
|---|---:|---:|---:|---:|
| 540 RPM | 13888889 | 2776 | 115712 | 925.696 μs |
| 900 RPM | 8333333 | 1330 | 69440 | 555.520 μs |
| 1320 RPM | 5681818 | 639 | 47328 | 378.624 μs |

900 RPM 时体积刷新约 15 Hz，二维扫描约 1800 面/秒。低于约 285.5 RPM 时，保持值达到 6000 上限：RPM 仍可正常回传，但显示会提示 `LIMIT`，不能保证一转恰好显示 120 面。高转速测量仍受 36 ms 脉冲拒绝窗口限制。

## 蓝牙及上位机

照常运行根目录 `start_ch9141.cmd`。原有 `STATUS` 行例如：

```text
RPM:900 DLY:555 F:0 S:0 MODE:BRUSH ... TARGET_RPS:15 SLICES:120
SYNC:TRACK DO:0 LEVEL:0 EDGES:20 ACCEPT:18 REJECT:2 PERIOD_CLK:8333333 FRAME_CLK:69440 SCAN_HZ:1800 SLICE_US:555
```

`F/S` 保留原兼容字段，在本 FPGA 工程中不表示电机 PWM 或同步锁定；请查看新的 `SYNC`：

| 状态 | 含义 |
|---|---|
| `TRACK` | 实测转速有效，实际扫描间隔符合一转 120 面的整数取整要求 |
| `ADJUST` | 测到新周期，扫描间隔还在切换 |
| `ACQUIRE` | 已收到第一条脉冲，等待完整下一圈 |
| `LOST` | 无有效脉冲锁定；RPM=0，恢复 15 转/秒默认自由显示 |
| `LIMIT` | 测速有效，但扫描保持时间已达到硬件上下限 |

`EDGES` 为通过电平滤波的上升沿数；`ACCEPT` 为通过拒绝窗口的真实脉冲数；`REJECT` 为过近而丢弃的脉冲数。自由显示合成脉冲不会增加这三个计数。`DO` 是同步后的输入电平，`LEVEL` 是滤波后电平；两者是采样状态，不是脉冲计数。

## 寄存器接口

桥 ID 升为 **VXB4 / 0x56584234**，基址由本次 XSA 生成，画布寄存器和模式值不变。新 ELF 与新 BIT 必须配套使用。

| 偏移 | 内容 |
|---|---|
| `0x28` | 实测一转周期；读取时同时锁存下面五个诊断寄存器 |
| `0x2c` | flags：bit0 DO、bit1 LEVEL、bit2 有脉冲锁定、bit3 完整周期有效、bit4 扫描范围可支持、bit5 扫描限幅 |
| `0x30` | 滤波后的真实上升沿数 |
| `0x34` | 接受脉冲数 |
| `0x38` | 拒绝脉冲数 |
| `0x3c` | 实际相邻扫描面 `frame_done` 间隔时钟数 |

PS 必须先读 `0x28`，再读 `0x2c..0x3c`，保证同一快照。既有 `0x24` 圈计数保留原来的真实/自由显示事件语义，以免改变贪吃蛇步进和动画逻辑。
